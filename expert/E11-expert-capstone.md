# E11: Expert Capstone — Defend a Bank‑Grade Scoring Platform

> Professional option: replace this module with the 40 h [Industry Capstone](../capstone/industry/README.md) (industry benchmarks, MDD, validation report, workshop paper).

- **Image source:** lifecycle [Gambar 1, 2]; scope `[TAMBAHAN]`
- **Duration:** 10 hours | **Level:** Expert
- **Goal:** extend the intermediate capstone into a platform and defend it in a simulated **AI committee + model validation + OJK‑style examination** panel.

## Scope (choose the full set)

| Area | Requirement |
|------|-------------|
| Fraud real‑time | Streaming features (E01) + graph signals (E02) + conformal routing (E03), served with p99 ≤ 20 ms model time at 1 000 RPS (E07) |
| Fraud resilience | Red‑team results (E04) and abuse detection in production |
| Credit | Glass‑box PD + lifetime PD + scenario ECL (E05); limit‑increase policy with causal evaluation (E06) |
| Platform | GitOps on kind, Argo Rollouts canary with automated analysis, SLOs + burn‑rate alerts (E07) |
| Privacy | Federated or synthetic‑data experiment with assessment (E08) |
| Governance | Policy‑as‑code gates, evidence packs, OJK‑mapped framework (E09) |
| GenAI | Investigator copilot with CI evals (E10) |

## Milestones

| Milestone | When | Exit evidence |
|-----------|------|---------------|
| X0 Design review | Week 9 (2 h) | Architecture + threat model + risk tiering approved by a peer |
| X1 Integrated platform | Week 10 | `make expert-up` brings up the cluster via Argo CD; smoke tests green |
| X2 Live scenario | Week 10 | Scripted scenario: drift + new fraud ring + adaptive attacker → detection → challenger → policy gate → canary → (forced) rollback |
| X3 Panel defense | Week 10 end | 30 min: 15 min demo, 15 min questions from 3 roles (AI committee, validator, examiner) |

## Deliverables

- [ ] Architecture decision records for streaming, graph serving, runtime choice, FL/synthetic choice
- [ ] Evidence packs for both models generated by E09 tooling
- [ ] SLO report (1 week simulated traffic): availability, p99, error budget consumption
- [ ] Red‑team report and residual‑risk acceptance
- [ ] ECL report with scenario sensitivity
- [ ] Copilot eval report
- [ ] Post‑incident review of the forced rollback (blameless format)

## Definition of Done

- [ ] Scenario X2 runs end‑to‑end from one script with no manual cluster commands.
- [ ] All policy gates evaluated and logged; one gate demonstrably blocks a bad challenger.
- [ ] Canary aborts automatically on injected regression; rollback ≤ 5 minutes.
- [ ] Every number in the defense slides traceable to an MLflow run, report, or dashboard.
- [ ] Panel questions answered or logged as findings with owners.

## Rubric (100 %)

| Criterion | Weight |
|-----------|--------|
| Technical depth & correctness (streaming, graph, credit risk, serving) | 25 % |
| Rigor of evaluation (CIs, ablations, OPE, coverage) | 15 % |
| Reliability & operations (SLOs, GitOps, rollout, incident review) | 15 % |
| Security, robustness & privacy | 15 % |
| Governance & regulatory alignment (OJK, PSAK 109, UU PDP) | 20 % |
| Panel defense & communication | 10 % |

Each criterion scored 1–4 using the [expert rubric](README.md#expert-rubric-per-module). Pass ≥ 75 %.
